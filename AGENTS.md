# Calendar Sidebar

Always-on-top Windows desktop sidebar showing today's Google **and** Microsoft Calendar events. PyQt6 hosts a WebEngine that renders a Svelte/SvelteKit frontend; a FastAPI/uvicorn backend runs on a background thread and handles OAuth2 + event CRUD per provider. A system tray icon provides show/hide and quit.

## Architecture

```
widget.py    PyQt6 window, tray icon + server thread launcher
server.py    Composition root: reads env, wires providers, builds app/server
backend/     Provider-agnostic backend (imports never touch os.environ)
  models.py    CalendarEvent domain model
  auth.py      AuthProvider interface + TokenStore + OAuthStateStore
  provider.py  CalendarProvider interface + error taxonomy
  google.py    GoogleAuth + GoogleCalendarProvider
  microsoft.py MicrosoftAuth + MicrosoftCalendarProvider (Graph)
  registry.py  ProviderRegistry: lookup + cross-provider aggregation
  app.py       FastAPI app factory (dependency-injected registry)
src/         Svelte/SvelteKit frontend (adapter-static)
build/       Compiled frontend — generated by bun run build (gitignored)
run.vbs      Silent Windows launcher (hides the console)
log/         Runtime log files: widget.log, server.log (gitignored) — the only output when run via VBS
.env         Google + Microsoft OAuth credentials (gitignored)
.tokens.json Persisted OAuth tokens, keyed by provider (gitignored)
```

### Dependency injection

`server.py` is the only module that knows which concrete providers exist. It
builds a `ProviderRegistry` of `ProviderBundle(auth, calendar)` pairs and passes
it to `backend.app.create_app(registry)`. Routes declare their dependency via
`RegistryDep` (`Depends(get_registry)`), and each `CalendarProvider` receives its
`AuthProvider` by constructor injection. Adding a third provider means writing
two classes and one line in `build_registry` — no route changes.

## Running

```
bun install          # install frontend deps (once)
bun run build        # compile Svelte frontend (required once)
uv run widget.py     # start the app (uv handles all Python deps)
```

Or double-click `run.vbs` for a silent, no-console launch. All log output goes to `log/`.

`bun run check` runs `svelte-check` for frontend type errors.

## Ports

The API server binds 8764 by default and scans upward for a free port if it's taken. Each provider's redirect URI (`GOOGLE_REDIRECT_URI`, default `http://localhost:8764/api/auth/callback`; `MICROSOFT_REDIRECT_URI`, default `http://localhost:8764/api/auth/microsoft/callback`) must match the registered port in the provider's console — if the server falls back to another port, first-time login needs the matching redirect URI set accordingly. Once a provider's token exists, the port doesn't matter for it.

## Local API hardening

The API is bound to `127.0.0.1` and is only meant to be reached by the bundled WebEngine view. Do not loosen any of the following:

- `TrustedHostMiddleware` allows only `127.0.0.1` and `localhost`, so a DNS-rebinding page cannot reach the API.
- `/docs`, `/redoc`, and `/openapi.json` are disabled.
- The SPA catch-all resolves each request path and rejects anything that escapes `build/` (e.g. `/%2e%2e%2f.env`).
- OAuth `state` is generated per login, bound to the issuing provider, stored server-side for 10 minutes, and validated single-use on the callback. The callback dispatches on the state's provider, so a Microsoft state can't be replayed against Google's callback (or vice versa).
- `.tokens.json` is written atomically, guarded by a lock against concurrent refresh, and chmodded `0600`.

A named-mutex guard prevents a second instance from starting.

## OAuth setup

Both providers are optional — configure either or both. Unconfigured providers
are reported as such and their Connect button is hidden.

### Google

1. Create an OAuth 2.0 credential in Google Cloud Console (type: web application).
2. Add `http://localhost:8764/api/auth/callback` as an authorised redirect URI.
3. Copy `.env.example` to `.env` and fill in `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.
4. Open the app and click **Connect Google Calendar**. The widget copies a
   Google consent URL to the clipboard — paste it into any browser to sign in.
   (OAuth can't run inside the embedded WebEngine: Google blocks webviews and
   passkey prompts don't work there.) The callback stores the token and the
   widget picks it up on its next status poll.

### Microsoft

1. Register an app in Azure / Entra ID (**App registrations → New registration**).
2. Under **Authentication**, add a **Web** redirect URI:
   `http://localhost:8764/api/auth/microsoft/callback`.
3. Under **API permissions**, add Microsoft Graph **delegated** permission
   `Calendars.ReadWrite` and grant admin consent if your tenant requires it.
   The app also requests `offline_access` (for refresh tokens) and `User.Read`
   is not needed.
4. Create a client secret under **Certificates & secrets**.
5. Fill in `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET` (and optionally
   `MICROSOFT_TENANT_ID`, default `common`) in `.env`.
6. Click **Connect Microsoft Calendar** — same clipboard/consent-URL flow as
   Google.

## Calendars

`GET /api/events` merges today's events from **every calendar of every
connected provider**, tagging each with `provider` (e.g. `google`/`microsoft`),
`calendarId`, and the calendar's colours. One provider failing does not blank
the sidebar: failures are logged and the other providers' events are returned;
the request only errors when every authenticated provider fails. All-day events
are still returned (they count for the empty state) but the frontend filters
them out of the grid.

`PATCH`/`DELETE /api/events/{id}` accept `?provider=` and `?calendar_id=` so an
event is edited through the provider/calendar it came from; `POST /api/events`
takes an optional `provider` field (defaults to the first connected provider).
Setting `GOOGLE_CALENDAR_ID` / `MICROSOFT_CALENDAR_ID` pins that provider to a
single calendar instead of merging.

Google OAuth needs both `calendar.events` and `calendar.calendarlist.readonly`;
Microsoft needs `Calendars.ReadWrite` (plus `offline_access` for refresh).
Tokens saved before a required scope existed are reported as unauthenticated,
so re-running the login flow is expected after upgrading.
`OAUTHLIB_RELAX_TOKEN_SCOPE=1` is set at import so Google's normalised scope
list doesn't make oauthlib raise a bare `Warning` (which would 500 the
callback); the granted scopes are validated explicitly instead.

`TokenStore` keeps every provider's blob under its own key in `.tokens.json`
and migrates a legacy flat Google file on first write.

## Debugging

When launched via `uv run widget.py` or `run.vbs`, uvicorn runs inside the widget process, so **all** output — API and OAuth messages included — lands in `log/widget.log`. `log/server.log` only appears when you run `uv run server.py` standalone.

Key log lines to look for:

| Log message | What it means |
|---|---|
| `No calendar provider configured` | `.env` has no Google or Microsoft credentials |
| `Cannot start OAuth flow` | `/api/auth/{provider}` has no usable config — returns 503 |
| `Generated {provider} consent URL for manual sign-in` | Normal: Connect copied a sign-in URL to the clipboard |
| `Token file not found for {provider}` | Not yet authenticated — click Connect |
| `API request rejected — no provider authenticated` | 401 on event fetch; connect a provider |
| `Stored Google credentials are invalid and cannot be refreshed` | Token unusable with no valid refresh token — 401 + reconnect prompt |
| `Google credential refresh failed` / `Microsoft token refresh failed` | Refresh token revoked; re-authenticate |
| `OAuth callback rejected — missing, unknown, or expired state` | State was not issued by this process (or is older than 10 min); restart the login flow |
| `OAuth callback rejected — ... cross-provider state` | State was issued for a different provider; restart the login flow |
| `Google token exchange failed: ...` | `flow.fetch_token` raised; the loguru traceback has the real reason (used/expired code, `invalid_grant`, etc.) |
| `Microsoft token exchange failed: ...` | Graph token endpoint returned 4xx; body is logged |
| `Google/Microsoft did not grant required scope(s): ...` | Consent omitted a scope; check the consent screen / API permissions |
| `API server not ready yet — retrying` | Widget waits for the port to bind before loading the UI |
| `Retrying UI load in ... ms` / `WebEngine failed to load ... (attempt n/5)` | Page load failed; the widget retries with backoff |
| `Giving up on UI load` | Five consecutive load failures — restart the app |
| `Another Calendar Sidebar instance is already running` | Single-instance guard tripped |
| `Server will run on port ... but ... redirect URI points at ...` | Port fallback broke first-time login; see Ports |

## Conventions

- Python: `uv` only (no pip), f-strings, full type hints, loguru for all logging.
- No `import *`.
- Keep `widget.py` focused on the Qt layer; keep business logic in the `backend/` package. `server.py` is the composition root — env parsing and provider wiring only.
- `backend/` modules must not read `os.environ`; configuration is injected from `server.py`.
- New providers implement `AuthProvider` + `CalendarProvider` and are registered in `build_registry`.
- Shutdown path: Qt quit → `CalendarWindow.shutdown()` sets uvicorn's `should_exit` for a graceful stop.
